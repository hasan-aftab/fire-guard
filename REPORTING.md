# PDF reporting

Authenticated, verified users can request `GET /reports/pdf` with `type`, `client_id`, optional `site_id`, `date_from`, `date_to`, optional `include_entered_in_error=1`, and optional `disposition=download` (default: inline). Dates use `YYYY-MM-DD`; the selected site must belong to the client. The four types are `inspection`, `service`, `maintenance`, and `audit`.

Reports are generated on demand from current records. No PDF artifact or report snapshot is saved, so a later generation may differ if client, site, asset, or inspection data changes. The planned report history feature is the place to add retained, immutable PDF artifacts and disk/path metadata. Report generation never changes source records.

The default renderer is `spatie/laravel-pdf` with `dompdf/dompdf`, selected by `LARAVEL_PDF_DRIVER=dompdf` in `config/laravel-pdf.php`. This is the simplest current deployment choice because the repository does not specify a Chrome, Node, Docker, or PDF service installation on its VPS. The report templates use print CSS, tables, A4 paper, and private image data URIs, which are compatible with DOMPDF. The production PHP runtime needs the Composer platform requirements (including DOM and mbstring) plus GD for report photo resizing. No browser, Node, or external PDF service is needed for this driver. The actual VPS configuration must be checked before deployment.

The package also supports `browsershot`, `chrome`, `weasyprint`, `gotenberg`, and `cloudflare`. To switch, install the corresponding driver package and runtime/service described in the package documentation, then set `LARAVEL_PDF_DRIVER`; report data collection and templates need no driver selection code. DOMPDF has limited modern CSS support; these templates intentionally avoid grid and JavaScript. Driver-specific production output should be checked before switching.

Private inspection images are read using each photo's recorded `storage_disk` and `storage_path`, so local and S3-compatible disks use the same code. GD produces a temporary 1200-pixel JPEG data URI; originals are untouched. Missing, corrupt, over-20-MB, or over-16-megapixel files display `Image unavailable`. Requests are capped at 30 sites, 200 assets, 200 certificates, 150 inspections, and 24 photos; users can narrow site or dates if a report exceeds a limit. These limits keep synchronous rendering bounded.

`REPORT_COMPANY_NAME`, `REPORT_COMPANY_PHONE`, and `REPORT_COMPANY_EMAIL` control the PDF letterhead. An optional PNG/JPEG logo can be stored privately and selected with `REPORT_LOGO_DISK` and `REPORT_LOGO_PATH`; the report reads it through Laravel storage and embeds it, up to 1 MB. The final company logo, contact details, signature format, service/maintenance activity classification, and formal audit layout need client input. Current service and maintenance reports identify the inspection records they draw on and make no claim that an inspection was a completed service or maintenance job. The audit report is a system record summary, not a regulatory conclusion.
